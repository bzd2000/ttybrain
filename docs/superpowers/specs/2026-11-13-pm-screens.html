Screen 2 · project tab

Project context

The eighth tab: a long Markdown document per project with background, scope, architecture, contracts and links. It's rendered as formatted Markdown and scrolls. It's separate from the one-paragraph description on Overview, which stays short for lists and board packs. You'll fill it later through an MCP integration; for now the field exists and can be set from the CLI or your editor.

Notes tab: a free-text area for during the meeting, plus a/D to log an action or decision on the spot, linked to this meeting and the selected agenda item's project.

Export tab: a preview of the Markdown pack (agenda + one prep block per project), with w to write it to a file you choose. The same output comes from pm report board M-4.

"Ask for this meeting" is new: one short field per agenda item for what you need from the board. It's often the point of the item, so it gets its own place in the pack.

Side pane · any screen

Inline Copilot session

Press c on any screen and a GitHub Copilot CLI session opens in a pane on the right, next to what you were looking at. It is the real Copilot CLI running inside pm, started in your pm data folder and told which project or person you are on. While the pane has focus every key goes to Copilot; one key hands the keyboard back to pm. When Copilot changes data, the left side refreshes.

How it is built: OpenTUI's core package has an embedded terminal component. It is only the emulator, so pm itself starts copilot in a pseudo-terminal, feeds its output into the component and sends your keystrokes back. What you see is Copilot's own interface; the transcript above is an approximation.

Context: the session starts in the pm data folder, where Copilot's guide lives, and pm passes the current screen (here project CRM) as the opening context. Copilot works through the same pm commands as before, so nothing new to maintain.

One session: hiding the pane does not stop Copilot. The green ● copilot marker in the header shows a session is alive, and c brings it back with its history.

Alternative: the GitHub Copilot SDK drives the same CLI engine programmatically, with streaming and custom tools. pm could then draw its own chat pane and offer its operations as tools instead of shell commands. Nicer integration, clearly more work, and the SDK is newer.

For you to decide

Open questions on these screens

  1. Is Attention the right home screen, and are its seven panels the right ones?
  2. Is 30 days the right "no contact" threshold for stakeholders, or should it depend on their influence?
  3. The meeting prep adds an "Ask for this meeting" field per agenda item. Keep it?
  4. Copilot pane: embed the real Copilot CLI (as drawn), or build a pm-native chat on the Copilot SDK? And is Ctrl+] acceptable as the key that gives the keyboard back to pm?
  5. Anything you'd expect to see on a screen that isn't there?
